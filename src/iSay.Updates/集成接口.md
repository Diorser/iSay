# 更新底座集成接口

首版只支持 `application` 应用文件组件。引擎、词典、TSF、共享 .NET、更新器自身和信任配置必须由完整安装器维护；不能把这些文件塞入应用包。更新器按需启动，不常驻。

## 桌面接口

```csharp
var configuration = UpdateConfiguration.Load(Path.Combine(AppContext.BaseDirectory, "release.json"));
using var client = new UpdateClient(configuration);
var result = await client.CheckAsync(currentVersion, cancellationToken);
// NotConfigured：发布域名或公钥未配置，不发生任何请求。
// UpToDate：已验证清单且没有更高版本。
// Available：可以展示 result.Release.Manifest.ReleaseNotes。
var prepared = await client.DownloadAsync(result.Release!, cacheDirectory, progress, cancellationToken);
var requestPath = UpdateLauncher.WriteRequest(prepared, cacheDirectory);
await UpdateLauncher.StartAsync(requestPath, cancellationToken);
// 握手成功后，由桌面正常保存状态并退出；更新器等待明确的 PID 与启动时间。
```

`UpdateLauncher` 自动记录当前进程 ID、启动 UTC ticks；更新器只接受来自同一安装目录 `iSay.exe` 的请求，不强杀进程。更新器程序名固定 `iSay.Updater.exe`，与主程序同目录。默认发布配置为空，因此此提交没有假设任何现有域名或线上更新服务。

`StartAsync` 最多等待 20 秒安装前握手，成功后桌面才正常退出；更新器最多再等待主进程 2 分钟。启动时间用于防 PID 复用。等待超时取消更新，不结束父进程。应用替换失败且自动回滚完成时，更新器尝试重新打开原版本；回滚发生冲突时保留备份和事务记录，交给完整安装器修复。

## 配置与签名格式

`release.json` 用 `UpdateJson.Options` 读写：camelCase，严格字段名，拒绝未知字段。主要字段为 `applicationId`、`channel`、`architecture`、`manifestUrls`（HTTPS 镜像数组）、`publicKeys`（keyId → PEM RSA 公钥）、`minimumSequence` 及体积/文件数限额。请勿在客户端配置中保存私钥。

清单信封字段固定：`envelopeVersion: 1`、`keyId`、`algorithm: "RSA-SHA256-PKCS1"`、`payloadBase64`、`signatureBase64`。签名使用 RSA≥2048、SHA256、PKCS#1 v1.5。签名对象是 `ManifestCodec.CanonicalPayload(manifest)` 的 UTF8 字节；对象属性递归按 Ordinal 排序，无空白，数组顺序不变，使用默认 .NET JSON 字符转义。发布脚本应直接调用 `ManifestCodec.Sign(manifest, rsa, keyId)`，避免自行实现规范化。

正文 `ReleaseManifest` 包含 schemaVersion=1、applicationId、version（数字版本）、channel（stable/preview）、architecture（win-x64/win-arm64）、sequence（递增整数）、publishedAtUtc、expiresAtUtc、minimumUpdaterVersion="1.0.0"、releaseNotes（zh-CN/en）、components。

每个组件包含 id="application"、version、packageUrls（HTTPS 镜像数组）、sha256、size（ZIP 精确长度）、maximumExpandedBytes、files；每个文件必须有 path（相对路径，使用 `/`）、sha256、size。ZIP 文件必须与签名清单精确一致，不能有未知文件、链接或重复路径。

签名有效期最长 180 天。客户端验证签名、产品/通道/架构、版本、时间、序号、包长度/哈希、每文件哈希、展开总量及安全路径。成功安装后保存单调序号；相同或更旧版本不自动安装。

事务记录位于安装目录 `.update-state/`，替换前完成全部安全展开和目标检查，旧文件通过移动保存，异常逆序恢复。单调状态写入构成提交边界；下一次更新器运行可恢复未完成事务。成功更新仅保留最近一次备份；失败及恢复冲突记录保留。ZIP 必须为单卷普通 ZIP，不使用 ZIP64。清单最大 3 MiB、每次流式读取缓冲不超过 80 KiB，展开量和文件数受签名清单及本地配置双重约束。

## 发布与验收边界

独立更新器仍需 .NET 10，推荐随首装完整安装器检测并离线安装 Windows Desktop Runtime 10；更新包不重复携带运行时。公开发布前须填写真实 HTTPS 发布地址、公钥，完成签名离线保管与轮换流程，并在全新 Windows 虚拟机验证安装、下载、取消/续传、占用失败回滚、重启。当前不会部署 Cloudflare、注册域名或执行真实安装。
