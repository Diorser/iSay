## 保留现有能力的解决路径

1. **维持当前原生方案，公开完整包。** 当前已按维护者选择公开完整安装预览、启用官网下载入口。后续仍需取得覆盖具体 EXE、DLL、模型、词库版本、适配修改和远端服务使用的许可或授权，补齐相应原始声明，才能形成授权依据明确的商业发行方案。
2. **安装官方组件，再由 iSay 外置适配。** 能减少自行再分发第三方二进制的问题，但当前适配依赖固定版本与哈希，且存在修改副本行为；不能只把 DLL 改为用户自行下载就宣称全部问题解决。需要重新确认公开接口、版本检测和服务使用范围。
3. **保留豆包技术体系，使用正式语音服务接口。** 可通过官方豆包语音 API 实现流式输出，避免提取输入法内部组件；需要另行接入，处理账号、额度和费用。词典、学习和整理不一定与现有组件一一等价。产品主密钥不能放进开源客户端，需要用户自配凭据或受控服务端。

没有单独授权时，第 3 条是更适合商业产品评估的方向；它会改变当前依赖和成本，必须先明确产品选择，不能暗中替换现有识别方案。

## 已落地的独立发布入口

`scripts/发布/发布完整安装包.ps1` 只处理完整安装器，不要求配置自动更新地址、R2 或清单签名私钥。

```powershell
# 只生成下载元数据、校验和与双语发行说明，不上传。
pwsh -File scripts/发布/发布完整安装包.ps1 -ArtifactDirectory <本机发行目录>

# 上传到仓库维护者可见的草稿，并回下载真实安装器和校验文件核对。
pwsh -File scripts/发布/发布完整安装包.ps1 -ArtifactDirectory <本机发行目录> -Mode Draft -SourceRevision <40位源码提交SHA>

# 只读复核已有草稿或公开发行，恢复元数据，不修改或覆盖远端资产。
pwsh -File scripts/发布/发布完整安装包.ps1 -ArtifactDirectory <本机发行目录> -Mode Verify -SourceRevision <40位源码提交SHA>

# 维护者明确承认第三方范围尚未核实，选择公开安装预览；不代表已取得授权。
pwsh -File scripts/发布/发布完整安装包.ps1 -ArtifactDirectory <本机发行目录> -Mode Publish -SourceRevision <40位源码提交SHA> -UseRangeDownload -AcknowledgeUnverifiedThirdPartyRights
```

脚本默认不公开。`Publish` 模式需显式选择已确认权利范围的 `-PublicRedistributionApproved`，或承认范围仍未确认的 `-AcknowledgeUnverifiedThirdPartyRights`；后者不会把元数据记成已取得授权。同名已公开发行不会被替换。已有草稿的目标提交必须匹配；公开后可用 `Verify` 只读恢复，失败会保留前次核验元数据。默认下载超时 600 秒，可用 `-DownloadTimeoutSeconds` 调整至 1800 秒，超时会结束本次下载子进程。源码提交参数表示发行标签目标，不代替可重复构建证明。

已接入自动更新的发行传入 `-AutomaticUpdatesEnabled`，脚本会额外核对布局、公钥、签名和实际应用包后标记官网元数据。完整签名发布步骤见[自动更新使用与发布](自动更新使用与发布.md)。

官网只使用公开发行完成、真实回下载验证成功后的元数据，不能链接维护者草稿或把源码 ZIP 当安装器。公开安装预览完成后，`website/dist/downloads/windows.json` 使用已核对的 `available` 元数据；网络异常、未公开状态或错误地址均保留源码入口。普通下载遇到过流中断与超时，现可加 `-UseRangeDownload` 使用限定官方主机的分块下载；每块核对 HTTP 206、Content-Range 与长度，最终再核对完整 SHA256，凭据仅保存在内存。独立发布模拟回归 29 项、官网入口回归 48 项通过，已纳入公开 CI。
