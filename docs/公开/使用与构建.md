# 使用与构建

当前公开版本为 iSay 0.10.1 源码预览，TSF 输入组件版本为 0.9.7。仓库不包含第三方原生引擎、个人数据、完整安装包或发布凭据。

## 构建环境

- Windows x64，.NET 10 SDK。
- 构建原生输入组件：CMake 3.24+、Visual Studio 2022 C++ 工具链与 Windows SDK。
- 运行已构建的 WPF 客户端：.NET 10 Windows Desktop Runtime x64。只有 .NET 普通运行时不够；开发机的 SDK 通常已包含所需桌面运行时。
- 原生输入组件和另外准备的第三方组件可能需要 Visual C++ v14 运行库；x86、x64 组件分别使用对应架构的运行库。

安装脚本设置的系统门槛为 Windows 10 2004（19041）。该门槛不表示已经在所有 Windows 版本、语言和输入宿主上完成验收。

## 托管程序

在仓库根目录执行：

```powershell
dotnet build src/iSay.Desktop/iSay.Desktop.csproj -c Release
dotnet build src/iSay.Updater/iSay.Updater.csproj -c Release
dotnet build src/iSay.ReleaseTool/iSay.ReleaseTool.csproj -c Release
```

这些命令会正常还原 NuGet 包；不会准备第三方二进制、安装 TSF 或修改开机启动。桌面输出位于 `src/iSay.Desktop/bin/Release/net10.0-windows/`。

缺少原生依赖时仍可编译客户端，但默认内置识别、整理、学习及词典的对应功能无法完整运行。仓库内的冻结清单只描述完整性要求，不提供第三方二进制，也不授予其使用或再分发权限。

## TSF 与维护程序

在已安装 Visual Studio 2022 C++ 工具链的环境中执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/构建组合输入组件.ps1 -Architecture x64
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/构建组合输入组件.ps1 -Architecture x86
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/构建组合输入安装器.ps1
```

输出分别位于 `artifacts/组合输入组件/x64`、`artifacts/组合输入组件/x86` 和 `artifacts/组合输入安装器`。构建不等于注册；系统注册与当前用户启用属于两个不同步骤，最终应由完整安装器完成。不要在正在使用输入法的日常环境中直接替换已加载的 DLL。

如 CMake 未位于脚本使用的位置，可使用等价命令指定工具链：

```powershell
cmake -S src/iSay.TextService -B artifacts/手工构建/tsf-x64 -G "Visual Studio 17 2022" -A x64
cmake --build artifacts/手工构建/tsf-x64 --config Release
cmake -S src/iSay.TextService -B artifacts/手工构建/tsf-x86 -G "Visual Studio 17 2022" -A Win32
cmake --build artifacts/手工构建/tsf-x86 --config Release
cmake -S src/iSay.TextService.Setup -B artifacts/手工构建/setup -G "Visual Studio 17 2022" -A x64
cmake --build artifacts/手工构建/setup --config Release
```

## 语音与整理服务

内置适配器继续使用现有第三方原生组件与服务，未被另一家识别引擎替换；产品命名调整不会改变其技术或许可依赖。需要自行确认组件来源、服务可用性和相关授权。

也可在“设置 → 服务与连接”选择“兼容的HTTP语音接口”，填写支持 `/audio/transcriptions` 的接口地址、模型与密钥。兼容接口的分段方式、延迟、识别语言和费用取决于服务实现，不等同于内置适配器的实时行为。智能整理页可选择自定义 AI 接口；使用前应确认其协议、隐私条款和服务费用。仅配置整理接口不会提供语音识别能力。

初次使用时：

1. 准备可用的语音服务，选择麦克风，并检查 Windows 麦克风权限。
2. 使用界面录音按钮或右 Alt 开始，再次按下结束。新配置默认录音时静音、登录自启；可在设置调整。
3. 测试目标应用的输入框。TSF 组合模式需要输入组件已正确安装；不支持的输入框可试普通文本兼容模式，或先复制识别结果。
4. 在设置最后的“关于”页切换中英文、查看版本或检查更新。

输入位置变化、应用失焦和手工编辑可能使组合失效；项目不承诺在任意应用、任意交错编辑情况下继续原组合。

## 回归检查

公开检查源码不附带本机日志、录音或测试账户。可在仓库根目录执行：

```powershell
dotnet run --project test/更新安全回归/更新安全回归.csproj -c Release
dotnet run --project test/发行发布预检回归/发行发布预检回归.csproj -c Release
dotnet run --project test/客户端核心测试/客户端核心测试.csproj -c Release
dotnet run --project test/配置恢复回归测试/配置恢复回归测试.csproj -c Release
node test/发行打包回归/Worker回归.mjs
```

Worker 检查另需 Node.js。回归通过不能替代真实 Windows 安装、麦克风、目标输入框和长时间运行验收。

## 安装与发行

`scripts/发布/构建Windows发行.ps1` 与 `scripts/安装/iSay安装包.iss` 提供完整发行的实现。它们还需要本地 `external/` 中符合冻结清单的原生组件、已构建的双架构 TSF、维护程序、Inno Setup 和经过验证的微软原始运行时安装器。公开仓库检出后不能独立生成全功能完整安装包。

完整离线安装设计会携带 .NET Desktop x64 和 VC++ x64/x86 安装器；检测到满足条件的环境后跳过安装，否则静默安装并保存诊断日志。系统依赖安装或 TSF 系统注册可能触发 Windows 管理员授权。完整安装包与小型应用更新包用途不同，不能用托管程序体积估算前者。

更新底座已包含 RSA 签名清单验证、哈希校验、续传与文件事务恢复；当前 `src/iSay.Desktop/release.json` 的更新地址和公钥为空，未启用正式在线发行。Cloudflare 更新文件 Worker 模板见 [更新服务配置入口](../../scripts/发布/Cloudflare/使用说明.md)，它与静态官网是两个独立部署。配置生产更新服务还需要控制签名私钥、设置客户端信任公钥并验证正式下载地址。文件事务回滚不包含新版本启动后的健康检查自动回退。

当前 Windows 10 虚拟机新机安装、真实麦克风出字仍待验收，8 小时资源测试也未完成；请先在隔离环境验证。

## 本机数据与诊断

默认数据目录为 `%APPDATA%\iSay\VoiceDesk`：

- `设置.json`：用户设置与受 DPAPI 保护的自定义服务密钥。
- `历史.json`：转写历史，默认启用并保留 30 天。
- `运行.log`：运行诊断；并非所有原生服务错误都能在其中完整呈现。

默认程序目录为 `%LOCALAPPDATA%\Programs\iSayVoiceDesk`。输入组件的安装诊断保存在安装目录的 `composition` 下，安装向导也会显示日志位置。报告问题时保留出错阶段与错误码，先移除私人正文、个人路径、词库、密钥和音频。
