# 自动更新使用与发布

从 0.10.6 开始，完整安装包附带官网更新清单地址和验签公钥，默认开启自动检查。0.10.5 及以前的安装包没有配置更新源，需要手动安装一次新版，之后才能使用这条通道。已有个人设置与开关选择会保留。

## 用户操作

启动后延迟 30–60 秒检查，其后约每 12 小时检查一次；录音、整理和收尾期间暂缓，空闲后继续。开关位于设置最后的“关于”页，该页和托盘菜单都可以手动检查。自动检查只取小型版本清单，不会自动下载整个安装器，也不会擅自退出程序。

发现新版本后，可查看说明、下载、取消、跳过此版本；下载完成并校验通过后，由用户选择安装并重启。安装前必须结束录音和整理。普通应用更新只包含桌面程序和必要托管资源；原生识别引擎、TSF、运行环境、更新器自身及信任配置的变更仍通过完整安装器维护。

## 与 LiteMonitor 的关系

沿用 LiteMonitor 的启动检查、设置开关、手动检查、新版提示和独立更新器交互。iSay 使用自己的 RSA 签名清单、包长度与 SHA256、逐文件校验、序号与版本防回退、失败事务恢复。网络请求保留系统 TLS 证书验证。

主源为 `https://isay-voice.pages.dev/updates/preview/win-x64.json`，备用清单为同仓库 GitHub Raw。应用 ZIP 位于 Pages 的内容哈希路径。该应用包小于 Pages 文件上限，无需 R2；完整安装器继续放 GitHub Release。

## 维护者发布

```powershell
# 首次准备或复用本机签名密钥与公开信任配置。
pwsh -NoProfile -File scripts/发布/官网更新发行.ps1 -Mode Prepare

# 每次更新先修改客户端版本，再生成完整安装器和签名应用包。
pwsh -NoProfile -File scripts/发布/官网更新发行.ps1 -Mode Build -ArtifactDirectory artifacts/Windows发行/新版本目录

# 核对信任配置、签名和实际包后，暂存官网清单与不可变下载对象。
pwsh -NoProfile -File scripts/发布/官网更新发行.ps1 -Mode Stage -ArtifactDirectory artifacts/Windows发行/新版本目录
```

将公开源码和签名清单推到 GitHub，再用既有 Wrangler Pages 流程部署 `website/dist`。ZIP 不进入源码 Git，由 Pages 直接上传。运行 `dotnet run --project test/在线更新验收/在线更新验收.csproj -c Release`，核对主源与备用清单、旧版发现新版、当前版本不重复提示和完整包下载哈希；该测试不安装应用。

线上源通过后，独立完整安装包发布脚本可传 `-AutomaticUpdatesEnabled`，它会再次核对签名发行内容，再在官网元数据中标记启用。更新元数据、README 和官网正文按实际发行同步。独立更新器成功、损坏、锁文件和回滚验收见 `test/独立更新器流程回归/验收说明.md`。

签名私钥在 `artifacts/更新信任/发布签名密钥.dpapi`，由 Windows 当前用户 DPAPI 加密。不要提交该文件，不要打印私钥或持久化明文；离机备份需同时规划恢复该 Windows 用户保护能力。丢失密钥时，不能靠网站更换公钥让旧版信任新密钥，必须通过可信完整安装器迁移。签名公钥属于公开配置，可以进入源码。

清单目前有效期 90 天，最长允许 180 天。即使版本没有变化，也应在到期前重新生成并签署清单；过期内容会被客户端拒绝，不能将到期错误解释为“已是最新版”。Pages 清单不缓存，内容哈希对象长期缓存。绑定正式域名时需同时更新客户端信任配置和发布脚本，旧地址应保留兼容期。
